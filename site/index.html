How it works

It reads what Claude Code already writes.

No proxy, no wrapper around claude, no API key. smif follows the session files and transcripts Claude Code keeps on disk, and a small local daemon turns them into state.

Features

Built for the moment a session needs you.

Write to any session

Press enter for the chat, type, send. If the session is idle, smif types into its tab as if you did. If it is busy and an agent owns its folder, a fork of the session answers from what it knows, and nothing is typed. A permission prompt is never answered for you.

Watchdogs

A reminder while a session still waits (10, 20, 30 minutes, then quiet). One alert when a working session goes silent. An optional one when a turn runs long.

smifstorefront still waits for you (12m)Bash: git push origin feat/checkout
smifinfra is silentnothing written for 10m: a long command, or stuck
smifpayments answeredAll 214 tests pass with -race

Saved prompts

The prompts you type ten times a day, under a name. p on a session, then 1–9. Or write @tests in any prompt.

[prompts]
tests  = "run the tests, report failures"
review = "review your last change"
ship   = "commit and open a PR"

The status line knows

Inside every Claude Code session, the others that need you. One glance, no tab switch.

Agents that ask each other

Background agents can send each other questions and events, routed by rules you write. A message's text never reaches a shell, and no tool reads inbound mail.

Principles

It stays out of the way.

Local only

Files on disk and a Unix socket. No account, no telemetry, no server of ours.

Never answers for you

A permission prompt or a question in a tab waits for you. smif shows it and brings the tab forward.

Zero setup

No config file needed. Run it and every open session is there.

Your config is the law

Commands come from your config only. Nothing a message says can reach a shell.

Questions

Fair questions.

Does anything leave my machine?

No. smif reads files Claude Code keeps on disk and talks to its daemon over a Unix socket that only your user can open. Notifications go through the system notifier.

Does it need an API key?

No. Reading sessions needs nothing. A fork that answers for a busy session runs claude with your own login.

Will it ever approve a permission prompt?

Never. It shows you what the session asks and brings its tab to the front with o. The answer stays yours.

What does smif install change?

It adds four hooks and a status line segment to ~/.claude/settings.json, a /smif command and an MCP server, and a launchd or systemd service. Every file is backed up first, and smif uninstall restores it.

Which terminals can it type into?

Terminal.app and iTerm2 on macOS, and tmux and herdr anywhere. Before typing it checks that claude is in the foreground of that tab. Elsewhere you still get the full view, the chat history and o.
